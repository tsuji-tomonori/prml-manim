# 5.2 ネットワーク学習

「ほぼ当たっている1点を外す方向へ重みを動かしたのに、なぜ全体の学習は良くなるのか」を追う日本語動画です。Manim Community Edition と VOICEVOX:WhiteCUL ノーマル（speaker 23）を使用します。

## 今回の物語設計

- 冒頭: seed 52 の同じ13点の回帰実験で、重みを0.700から最小二乗解0.815081へ動かすと、入力0.533の1点の絶対残差は約0.005から約0.091へ悪化する。視聴者に先に予想してもらい、全体の二乗誤差は約0.072から約0.013へ下がる意外な結果を見せる。
- 全編の問い: どの誤差を採点し、重みをどちらへどれだけ動かせば、個々の点に惑わされず全体を良くできるのか。
- 手掛かり: ガウスと二乗誤差、分類なら確率と交差エントロピー、誤差の谷と局所近似、勾配の成分、谷の幅と歩幅、バッチとオンラインを、直前の疑問への実験としてつなぐ。3.1・4.3・4.4の復習と偏微分の補足は各操作の直前に残す。
- 結末: 冒頭と同じ13点・同じ重み・同じ入力0.533の点に戻り、1点の悪化と全体の改善を再表示する。今回の最小二乗解は他の重みを固定した1次元断面の厳密解であり、後半の多峰性の地形と同一の誤差関数ではない。

## 成立条件と数値例

- 回帰は13点、seed 52、tanh の隠れユニット2つと線形出力の小さなネットワークです。説明のため1つの出力重みだけを動かします。他の重みを固定した断面なので、この最小二乗自体は凸です。最適な重みは0.815081、残差から求めた最尤ノイズ分散は0.00203433です。画面の重みカウンタは小数第2位まで表示しますが、曲線・残差・誤差は丸め前の同じ重みで計算します。
- ガウスの精度 β は分散の逆数です。重み最適化では β>0 を固定し、共通の分散を持つ独立なノイズを仮定します。最尤分散の分母は N（複数出力なら NK）です。不偏分散推定ではありません。
- 出力微分 y−t は一例について、対応する確率モデル・出力活性化・負の対数尤度を組み合わせた結果です。重みの勾配そのものではありません。
- 複数の独立二値出力と、排他的な softmax 分類を区別します。条件付き独立を仮定する場合も、隠れ層の特徴は共有できます。
- 多峰性の説明には `0.18(w²−2.2)²+0.16w+0.45` を用います。冒頭ネットワークの実際の誤差曲線とは別の教育用関数です。停留点は約 −1.53138、0.10149、1.42989です。
- 局所二次近似は近くでの近似です。ヘッセ行列が正定値なら停留点は厳密局所最小となりますが、ゼロ固有値がある場合は高次の項の検討が必要です。
- 勾配の計算量の比較は、原文の二次近似に基づく情報量の見積もりです。任意のネットワークの収束保証ではありません。一例あたりの逆伝播と、全データの評価を区別します。
- 二次誤差のヘッセ行列は固有値1と9、回転角0.4ラジアン。経路は `w ← w−ηHw` を NumPy で反復計算します。更新点間の移動は表示用の線形補間です。η=0.04、0.20で20回後の誤差は0.265942、0.000250088、η=0.24では7回後に4.184303へ増えます（初期値1.88145）。
- バッチ／オンラインは `y=w`、目標値 `[-0.9,0.1,1.4,0.6]` の明示的な例です。全体の最小値を取る重みは0.3。全体の停留点でも個別の勾配はゼロになりません。この凸の例で局所最小からの脱出そのものを実証したとは扱いません。

## 字幕・読み・同期

`narration_content.py` が10シーン・67段階・135文の正本です。`display` は記号を含む字幕、`speech` は読み上げ文です。字幕の MathTex は1.1で確認済みの実測文字高・数式本体の中心線・左右余白に合わせる方式を継承しています。

全135文を speaker 23 の `audio_query` で取得し、`reading_check.md/json` に初回と最終の読みを保存します。今回の読みでは「増えた分」が「フエタワケ」になったため、`speech` を「赤の確率が増えると」へ変更しました。「負の対数」「鞍点」なども `speech` 側で読みを指定しています。API の読み一覧確認と、音声を耳で通して聴く検査は別です。話速1.08、抑揚1.08です。

文ごとのPCM実測尺と台本・WAVのハッシュを `manifest.json` に保存し、同じ時計で字幕と動作を進めます。古い音声・欠落した音声では描画を停止します。各段階の末尾だけ約0.35秒の呼吸を加えています。`media/prml52_timeline.json` は描画時に作られる同期記録です。

## 最終検証

指定の `--disable_caching --flush_cache -ql` で全10シーン・76アニメーションを描画しました。今回の検証結果は `validation_results.json`、冒頭と結末の同一例を含む数値検証は `numerical_results.json` に保存しています。

`py_compile` と数値検証8群に成功しました。冒頭と結末は同じ13点・注目点・重みを使い、注目点の残差は0.0051849→0.0908371、全体の半二乗誤差は0.0718193→0.0132231です。二値分類の勾配と有限差分の最大誤差は1.94×10⁻¹¹、ガウスの負の対数の対応は誤差0です。全135字幕の最大幅9.3265625（上限12.9）、最大高0.69875（上限0.9）。字幕・画面の個数・番号・倍率に漢数字は見つかりませんでした。10 WAVのハッシュと台本・manifestの対応も確認しました。

映像612.733011秒、音声612.757333秒、差0.024322秒。H.264、854×480、15fps。`silencedetect=noise=-45dB:d=3` は3秒以上の無音0件、平均音量−26.5dB、最大−5.5dBでした。視覚補足・復習と結末の13文では、PCM発声開始が動作開始の64.2〜117.7ms後で、すべて対応動作中に入っています。映像と音声の全編デコードはエラーなく完了しました。

`review_video.py` は各段階の中央、強調・移動・色替えの途中と直後、数式字幕、視覚補足と復習の前後を抽出します。`validate_video.py` は字幕とmanifestの時計、音声の発声開始、動画のストリームと無音・音量を検査します。

最終動画から174フレームを抽出し、10シーンにわたる代表74箇所を元解像度のシートで目視しました。冒頭・結末・微分の補足・谷の軸・学習率の軌跡を含む5箇所は2倍拡大し、ラベルと目盛りの重なりも点検しました。レビュー画像はGit管理外の `media/review/` に置きました。
